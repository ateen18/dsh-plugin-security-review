### 问题 1（根因）：顶层静态导入宿主包，导致 ESM 解析失败

**现象**（2026-08-18 17:39 用户报告）：

```
Error: dsh: plugin tree failed to load: failed to apply loader entry include
(cordis:include): failed to import loader entry security-review
(dsh-plugin-security-review):
Cannot find package '@deepseek-ai/cordis-plugin-loader'
imported from D:\Coding\安全审查插件\lib\gate.js
Error [ERR_MODULE_NOT_FOUND]
```

**根因分析**：

- `lib/gate.js` 第 5 行在**模块顶层静态导入** `import { EntryTree } from "@deepseek-ai/cordis-plugin-loader"`；`lib/tools.js`、`lib/settings.js` 同样顶层导入了 `@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-settings`、`schemastery`。
- `package.json` 中 `dependencies` 为空，上述包仅声明为**可选 peerDependencies**。
- 插件目录 `D:\Coding\安全审查插件` 不在任何包含这些包的 node_modules 树内（它们只存在于全局 dsh 安装 `AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\node_modules` 内部），Node 的 ESM 解析自插件目录逐级向上找不到该包，**第一行 import 即抛错，整个插件树加载失败，dsh 崩溃**。

**解决措施**：

1. 新增 `lib/host.js` —— 宿主包解析器：
   - 通过 `process.argv[1]`（dsh CLI 入口脚本路径）向上定位 dsh 安装根（校验 `package.json` 的 `name === "@deepseek-ai/dsh"`）；
   - 使用 `createRequire` 锚定在 dsh 的 node_modules 内解析宿主包，并优先选取 exports 的 ESM（`import` 条件）构建，**保证与宿主共享同一模块实例**（`EntryTree` 为同一个类、schemastery 取 `.mjs` 构建），从而保证原型链补丁与类身份一致；
   - 保留从插件自身位置解析的兜底路径，兼容常规（非 symlink）安装场景。
2. `gate.js` / `settings.js` / `tools.js` 三处顶层静态导入改为**惰性动态导入**（运行时经 `host.js` 解析）。
3. `index.js` 的 `apply` 改为 `async`，并 `await` 三处惰性初始化完成后再注册门禁。
4. `package.json` 将 4 个宿主包从"可选 peerDependencies"移入真实 `dependencies`。

### 问题 2：`schemastery` 导入名错误（宿主使用带作用域 fork）

**发现时间**：2026-08-18 17:50 前后（诊断阶段）

**现象**：`lib/settings.js` 原代码 `import z from "schemastery"`。

**根因**：宿主 dsh 内安装的是**带作用域的 fork**——`@deepseek-ai/schemastery@3.18.1`，系统全局不存在无作用域的 `schemastery` 包。即使补装依赖，该导入也永远解析不到；且若解析到另一份副本，会导致 schema 类身份与宿主不一致。

**解决措施**：统一改为经 `lib/host.js` 动态导入 `@deepseek-ai/schemastery`（解析至宿主同目录下的 `lib/index.mjs`）。

### 问题 3（潜伏 bug）：ESM 严格模式下对函数 `name` 属性赋值

**发现时间**：2026-08-18 18:00 前后（首次模块图加载验证时暴露）

**现象**：`lib/index.js` 末尾 `apply.name = name;` 在模块加载即抛 `TypeError`（函数的 `name` 属性不可写，ESM 严格模式下赋值必然失败）。

**根因**：该插件此前从未成功加载到此处，故此缺陷从未暴露——修复问题 1 后才首次触发。

**解决措施**：改用 `Object.defineProperty(apply, "name", { value: name })` 方式（或等效安全写法）。
