# Web UI 安全审查模块优化记录

- **时间**：2026-08-20（GMT+8）
- **范围**：为 dsh-plugin-security-review 增加 Web 设置页可视化模块，并修复上线过程中发现的问题
- **关联文档**：`2026-08-20-install-gate启动崩溃修复报告.md`（上一轮稳定性修复）、`2026-08-20-插件评估与改进报告.md`

## 一、本次目标

让安全审查插件在 Web UI 中「看得见、点得动」：

1. 设置页左侧栏新增「插件安全审查」模块，展示当前全部已加载插件（含 dsh 官方内置插件，内置插件免审、不可卸载）；
2. 提供「一键安全审查」按钮，对全部插件执行完整静态审查；
3. 每个插件显示彩色风险圆点 + 一句话直观风险描述；
4. 非官方插件提供「卸载」按钮。

## 二、实现内容

### 2.1 宿主端（Host）

- **`lib/api.js`（新增）**：HTTP JSON API，全部 **loopback-only**（非本机请求一律 403）：
  - `GET /api/security-review/list` — 全部已加载插件 + 审查状态（官方/非官方、verdict、评分、风险摘要）
  - `POST /api/security-review/run` — 一键审查（`audit({fresh:true})`）
  - `POST /api/security-review/uninstall` — 卸载插件（`pnpm remove`，参数经正则 + 依赖清单双重校验，杜绝命令注入）
- **`lib/index.js`**：
  - `audit` 结果行新增 `version`、`risk`（safe/warn/danger）、`riskSummary`（直观风险摘要）字段；
  - `service` 新增 `list()`（全量插件视图，官方/非官方区分）、`runReview()`、`uninstall()`；
  - 检测到 `webServer` 时注册 API 路由（headless 无 webServer 自动跳过）。

### 2.2 客户端（Client）

- **`lib/client.js`（新增，手写 ModuleLoader bundle，零构建依赖）**：
  - 通过 `ctx.slots.register("settings.section", …)` 注册设置页左侧栏入口（id `security-review`）；
  - 组件提供：一键审查按钮、按风险分组列表（危险/风险/安全）、彩色圆点、卸载按钮（`confirm` 确认）、错误重试；
  - `package.json` 声明 `dsh.client`（inject `dsh-client-runtime`、`dsh-client-ui-settings`，platform `web`）与 `exports["./client"]`。

## 三、发现的问题与解决方式

| # | 问题 | 根因 | 解决 |
| --- | --- | --- | --- |
| 1 | 设置页「插件安全审查」入口出现，但列表报 **HTTP 404** | `webServer` 服务由 loader **同一并发批次**中的 web-app entry 提供；插件 `apply` 执行时 `ctx.get("webServer")` 可能返回 `undefined`，路由注册被**静默跳过**，webServer fallback 对未匹配路由回 404 | 路由注册改为**后台等待服务就绪**（轮询 `webServer` 最长 8 秒，不阻塞 `apply`）；三种结果都有明确日志（已注册 / 未就绪 / 注册失败），便于定位 |
| 2 | UI 上出现「小圆点：绿=安全…」说明文字，观感突兀 | 把用户描述设计意图的原话直接当文案打印到了界面 | 删除该说明；设计意图只作为实现依据，不进入 UI 文案 |
| 3 | 插件很多时列表过长、体感差 | 全部插件平铺展示 | 按风险**分组 + 折叠**：🔴危险、🟡有风险直接展开；🟢安全默认折叠（「▸ 展开」查看），空组不渲染 |
| 4 | 风险描述不直观，如「3 个 high 级别发现（dynamic-eval、client-browser-risk）」 | 直接暴露规则 id | 新增 `RISK_LABELS`（规则 id → 人话短语，如 `hardcoded-secret`→「硬编码密钥（API 密钥泄露）」）与 `summarizeRisks()` 聚合函数，按严重级别取前 3 项生成一句话摘要，如「有风险（评分 46）— 浏览器端数据泄露、动态执行/混淆代码」 |
| 5 | （设计保障）卸载接口被滥用风险 | — | loopback-only + 包名正则 + 依赖清单校验三重防护；官方插件无卸载按钮 |

# 2) 浏览器设置 → 插件安全审查：

## 六、遗留事项

1. 客户端为手写 ModuleLoader bundle，未经构建器校验——若设置页入口/交互异常，优先看浏览器 Console 与 dsh 终端日志；
2. 卸载是「从 profile 依赖移除」，运行中的插件实例需重启 dsh 才完全生效（UI 已提示）；
3. `RISK_LABELS` 覆盖 20 个主要规则，新增规则时需同步补充映射，否则摘要会退回显示评分。
