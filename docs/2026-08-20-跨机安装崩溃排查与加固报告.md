# 跨机安装（GitHub 源）崩溃排查与加固报告

- **时间**：2026-08-20（GMT+8）
- **背景**：插件上架 GitHub 后，在另一台电脑执行 `dsh plugin --profile web add github:ateen18/dsh-plugin-security-review` 出现 dsh 崩溃、agent 对话无法进行。
- **目标**：按四个维度彻底审查：① 对 dsh 本体危害；② 对其他插件的审查准确度；③ 是否影响其他插件安装；④ 其他影响使用的问题。

## 一、审查结论摘要

| 维度 | 结论 |
| --- | --- |
| ① 对 dsh 本体危害 | **低（加固后更低）**：模块图零外部依赖、apply 全程异常隔离、门禁 fail-open；已定位并修复 3 个高危薄弱点 |
| ② 审查准确度 | **中等偏高**：20 组规则 + 评分/策略/摘要对齐；已修复误报点（miner-wallet / plain-http / weak-metadata） |
| ③ 影响其他插件安装 | **中风险到已消除**：4 个 rc 依赖从 dependencies 改为 optionalDependencies |
| ④ 其他使用问题 | 已修复 client bundle 缺闭合括号、设置 API 注册时序等 |

## 二、按维度的问题清单与处置

### 维度 ①：对 dsh 本体的危害

| 风险点 | 说明 | 处置 |
| --- | --- | --- |
| **模块图加载失败 = dsh 启动失败**（fail-loud 契约） | 插件 entry 任何顶层 import 失败都会让 dsh 无法启动。历史上有两次真实事故：ERR_MODULE_NOT_FOUND（顶层静态导入宿主包）、SyntaxError（重复声明/缺括号） | ① 顶层零外部依赖（`@deepseek-ai/*` 全部经 host.js 惰性加载）；② apply 顶层 try/catch；③ 本报告同步修复了 client.js 缺闭合括号（ModuleLoader guard 的 else 块未闭合，属语法级事故） |
| **install-gate 改写全局 dsh bin.js** | 默认关闭；开启时若 dsh 目录只读/结构变化会写失败，已 fail-open；写入为原子 + node --check 自检 | 维持默认关闭；提供 CLI 手动管理 |
| **audit / import 门禁误伤官方插件** | 当 `findDshInstallRoot()` 解析失败（dshInstallRoot=null）时，旧逻辑会把「声明了 dsh.* 的包」一律纳入审查——官方插件可能被拦截为 no-op，导致 agent 工具缺失、对话异常 | **已修复**：scope 收紧——dshInstallRoot 未知时只审 profile 目录内的包；且 gate 对 resolve/scope 的异常一律放行（fail-open） |
| **审查器自身异常** | store.reviewPackage 失败降级为 warn 报告，不抛给调用方 | 已具备 |

### 维度 ②：对其他插件的审查准确度

| 问题 | 说明 | 处置 |
| --- | --- | --- |
| 「安全 + 风险描述」语义矛盾 | 摘要不区分严重级别，把 medium 提示与风险词混排 | 已修复：pass 不再罗列风险词，只显示「安全（评分 X）（存在 N 条中低危提示）」；warn/block 只列 critical/high |
| miner-wallet 误报 | `0x+40hex` 常命中哈希/常量；文档/注释误报 | 降为 low + 跳过文档文件 |
| plain-http 误报 | 文档/README 中的 http 示例被命中 | 跳过文档文件 + 排除 example.com/example.org |
| weak-metadata 非安全风险 | 缺 license/repo 属健康度问题 | 移出风险短语表（报告仍保留） |

### 维度 ③：是否影响其他插件安装

| 风险点 | 说明 | 处置 |
| --- | --- | --- |
| **rc 依赖硬依赖** | `dependencies` 含 `@deepseek-ai/dsh-settings@^0.1.0-rc.6` 等 4 个预发布包；另一台机器从 registry 安装时，若某 rc 版本缺失/不可解析，pnpm 安装直接失败 | **已修复**：4 个包移入 `optionalDependencies`，装不上不报错，运行时由 host.js 从 dsh 安装目录解析宿主副本 |
| install-gate 影响 `dsh plugin add` | 注入钩子若 import 失败会自动剥离并放行（fail-open），不阻塞安装 | 维持 |
| 卸载能力 | Web UI 卸载 = `pnpm remove`，参数经校验，不影响其他插件 | 维持 |

### 维度 ④：其他影响使用的问题

| 风险点 | 说明 | 处置 |
| --- | --- | --- |
| client.js 手写 bundle 语法事故 | ModuleLoader guard 的 else 块缺闭合括号（编辑中断遗留），浏览器端加载失败 | 已修复并全量校验（25 个 JS 文件语法级 0 失衡） |
| 设置 API 404 | webServer 由并发批次提供，apply 时可能未就绪 | 后台等待就绪注册（8 秒超时）+ 三种明确日志 |
| git 安装内容 | pnpm 对 git 依赖 clone 整个仓库（files 白名单不生效），test/、docs/ 会进入 store（无害，不执行）；`.workbuddy/` 若已提交会随仓库发布 | 建议把 `.workbuddy/` 加入 .gitignore 并确认未跟踪 |

## 三、本轮新增加固清单

1. `lib/gate.js`：scopeOfResolved 收紧（dshInstallRoot 未知时不审非 profile 内包）；gateBeforeImport 对 resolve/scope 异常 fail-open；
2. `lib/client.js`：ModuleLoader 不可用时降级（warn + 跳过），不再抛错；修复缺闭合括号；
3. `package.json`：`@deepseek-ai/*` 4 个 rc 包从 dependencies 移入 optionalDependencies；
4. 全量语法级校验通过（25 个文件 0 失衡）。

## 四、需要在另一台电脑执行的确诊步骤

```powershell
# 1) 确认本地版本是最新修复（先 pull 最新）
git -C D:/Coding/安全审查插件 pull
git -C D:/Coding/安全审查插件 status   # 确认 .workbuddy/ 未被跟踪（.gitignore 含 .workbuddy/）

# 2) 推送后，在另一台电脑重新安装（先移除旧安装）
dsh plugin --profile web remove dsh-plugin-security-review
dsh plugin --profile web add github:ateen18/dsh-plugin-security-review

# 3) 启动 dsh，把终端日志中与 security-review / plugin tree 相关的报错原样发回，例如：
#    dsh: plugin tree failed to load: ...
#    [security-review] ...
#    ERR_MODULE_NOT_FOUND / SyntaxError ...

# 4) 若 agent 对话异常：浏览器 F12 → Console/Network 截图（重点看 /plugins 客户端加载与 /api/security-review/* 请求）
```

## 五、结论

本插件在「模块图可加载」层面已做到零外部依赖（无任何顶层 `@deepseek-ai/*` 导入），配合 apply 全程异常隔离与门禁 fail-open，**理论上不会再因插件自身导致 dsh 无法启动**；审查准确度问题已对齐（摘要与结论一致、误报收紧）；安装链路风险（rc 依赖）已通过 optionalDependencies 消除。剩余不可在本机复现的变量（另一台机器的 dsh 版本、registry 可用性、安装路径）需按第四节步骤获取实际报错后继续定位。
